User-Agent Analyzer

A deliberately small Java 17 parser that identifies common browsers and operating systems without adding a runtime dependency.

Java 17JUnit 5CLI + libraryOpen source

The problem it solves

Sometimes a service needs a coarse answer from a user-agent string: which operating-system family sent the request, and which browser family and version does it advertise? Pulling in a comprehensive parser is not always justified for a command-line utility, a learning project or a tightly scoped internal use case.

User-Agent Analyzer keeps that trade-off explicit. It is a single-purpose parser with no production dependencies, an immutable result object, a command-line entry point and unit tests for the patterns it promises to support.

A compact API

The library surface is intentionally narrow: call UserAgentAnalyzer.parse and read the normalized result. A null, empty or unrecognized string returns Unknown values instead of throwing during an analytics or logging path.

UserAgentInfo info = UserAgentAnalyzer.parse(userAgent);

System.out.println(info.getOsName());
System.out.println(info.getOsVersion());
System.out.println(info.getBrowserName());
System.out.println(info.getBrowserVersion());

The packaged JAR also exposes a CLI:

java -jar target/user-agent-analyzer-0.1.0-SNAPSHOT.jar \
  "Mozilla/5.0 (...) Chrome/124.0.0.0 Safari/537.36"

Why detection order matters

Chromium-based browsers often include overlapping tokens. An Edge string can contain both Chrome/... and Edg/...; Opera and Samsung Internet have similar overlap. A parser that checks Chrome first will confidently return the wrong browser.

This implementation orders patterns from most specific to most general: Internet Explorer, Edge, Opera, Samsung Internet, Firefox, Chrome on iOS, Chrome and then Safari. OS matching similarly prioritizes Android and iOS before falling back to Linux or macOS markers.

Design invariant

When signatures overlap, a more specific product token must win before a shared engine token is considered.

Supported coverage

CategoryRecognized familiesNormalization
BrowsersChrome, Edge, Safari, Firefox, Opera, Samsung Internet, Internet ExplorerFamily plus advertised version
Desktop OSWindows, macOS, Linux, ChromeOSWindows NT mapped to common product versions
Mobile OSAndroid, iOS, iPadOSUnderscore versions normalized to dots

The JUnit suite covers Chrome and Edge on Windows, Safari on macOS and iOS, Chrome on Android and ChromeOS, Firefox on Linux, and Opera on Windows. Those tests document the supported contract more clearly than a long list of unverified claims.

Where this parser should not be used

User-agent strings are inconsistent and increasingly reduced for privacy. This project is not a device-fingerprinting library, a bot-detection product or a substitute for User-Agent Client Hints. It does not maintain the enormous device and crawler signature catalogs expected from a mature parser.

  • Use a maintained full parser when accuracy across long-tail devices and bots is business-critical.
  • Prefer feature detection over browser detection for frontend behavior.
  • Treat the parsed result as advisory metadata, never an authorization or security signal.
  • Expect Windows 10 and 11 to share the legacy Windows NT 10.0 token.

Build and inspect it

git clone https://github.com/gouravbyte/user-agent-analyzer.git
cd user-agent-analyzer
mvn -q test
mvn -q package

Read the source on GitHub. The project is intentionally small enough to understand in one sitting and straightforward to extend with a new ordered pattern plus a regression test.
