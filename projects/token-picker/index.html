TokenPicker

A Chrome extension for finding and copying authentication tokens during authorized API debugging—without sending them to a remote service.

JavaScriptChrome Manifest V3Local processingOpen source

Debugging without the DevTools hunt

Authenticated API debugging often starts with the same repetitive path: open DevTools, find the right request, inspect headers, locate the active token, copy it carefully, and repeat after rotation. TokenPicker packages that workflow into a small extension popup.

The tool is for developers inspecting sessions and applications they are authorized to access. It does not bypass authentication, mint credentials or make a token safer to share.

Security boundary

Use TokenPicker only on systems and sessions you own or are explicitly authorized to test. A copied bearer token is a credential and should be handled like a password.

How detection works

The background service worker tracks the active tab and supports three token sources:

  • Request headers: Bearer authorization, common session headers or a configured custom header.
  • Browser storage: on-demand scanning of localStorage and sessionStorage for likely token keys.
  • Cookies: on-demand matching of cookie names associated with the selected token type.

Detected values are deduplicated by token, associated with the first observed URL and capped by a configurable one-to-five item limit. The popup displays only the first and last four characters until the user chooses to copy.

Privacy choices in the implementation

The current source contains no remote analytics or token-upload endpoint. Runtime token data is held in memory and mirrored to chrome.storage.session for the popup. Settings live separately in local extension storage.

  • No token is copied automatically.
  • No detected value is included in the visible URL label.
  • Repeated values are stored once rather than once per request.
  • A clear action removes the working set.
  • Automatic cleanup can be enabled for browser close.

These choices reduce exposure, but they do not eliminate it. Clipboard managers, screen sharing, browser extensions and local malware can all observe secrets after they are copied.

Permission footprint

To inspect headers, storage and cookies across an active site, the extension manifest requests broad capabilities including webRequest, storage, cookies, scripting and host access. That breadth deserves explicit scrutiny before installation.

PermissionWhy it existsRisk to manage
webRequestObserve outgoing requests for configured token headersRequest metadata can be sensitive
cookiesRun an explicit cookie scanCookies may represent active sessions
scriptingInspect page-owned storage on demandInjected code must remain narrowly scoped
storagePersist settings and session resultsSecrets should remain temporary

A production release should narrow host access where possible, document exactly when each permission activates, add automated security tests and undergo an independent review before distribution.

Controls that make the tool predictable

The settings page makes token type, source, item limit and cleanup behavior explicit. Changing the mode requires a page refresh for header observation, while storage and cookie scans are user-triggered. The popup also exposes a manual clear control behind a confirmation step.

That separation keeps a sensitive developer tool understandable: configuration defines what is eligible, a deliberate scan controls when broader inspection happens, and the popup makes deletion visible.

Inspect before installing

Because this project handles credentials, source review is part of installation. Read the TokenPicker repository, inspect the manifest and background service worker, then load the unpacked extension only in a browser profile appropriate for development.
